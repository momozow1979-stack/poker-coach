# カメラ・ハンド読み取り 仕様（ライブ実卓）

ハンドレビューの入力を、**スマホのカメラでテーブル全体を1枚撮るだけ**で自動下書きする機能の設計。
ライブ（物理テーブル）のショーダウン時を対象とする。

> **重要（AGENTS.md ルール 2）**: API キーはアプリに埋め込まない。
> Vision の呼び出しは必ず Supabase Edge Function（サーバー側）から行い、写真も Edge Function
> 経由でモデルに渡す。クライアントコードにキーを置かない。**Vision は Claude（Anthropic）を使う。**

## 0. 位置づけ（できること / できないこと）

- **カメラ = カードの自動下書き**であって、全自動レビューではない。
- 写真から読めるのは**カード（ランク・スート）とその位置**だけ。ポジション・有効スタック(BB)・
  各ストリートのアクション履歴（誰がベット/レイズ/フォールドしたか、サイズ）は写真に写らないため、
  従来どおり**ユーザーが入力**する。カメラは `HandReviewInput`
  （`lib/features/hand_review/domain/hand_review_input.dart`）のカード欄をプリフィルする。
- 読み取り結果は**必ずユーザーが確認・修正してからレビュー実行**する（AGENTS.md ルール 1「捏造させない」と同思想）。

## 1. 撮影（1枚・縦向き）

- 撮影は OS 標準のカメラアプリ（`image_picker` の `ImageSource.camera`）を起動して行う。
  アプリ内に自前のライブプレビュー（`camera` パッケージ、撮影ガイドの枠つき）を持たせたことが
  複数回あるが、Web版では毎回別種の不具合（表示崩れ・プレビューが真っ黒になる・そもそも
  `camera_web` がレンズ種別の情報を一切持たないためレンズ選択が原理的に不可能、等）にぶつかり、
  実装をいくら直しても解決しなかったため標準カメラに一本化した。
  テーブル全体を画角に入れる・広角/超広角レンズへの切り替えは、ユーザーが普段使っている
  カメラアプリの操作（ズームUIなど）にそのまま委ねる。
- スマホは**縦向き**で、**ショーダウンで役が開いた状態を1枚**撮ってもらう。
- **画面全体にテーブル全体を入れる**（きっちり整列させる必要はない）。
- **自分の2枚は画面下側に入れて**撮ってもらう（自分のハンドを他と確実に区別するため）。
- 中央がボード、左右・上が他プレイヤーのハンド、という一般的な配置を前提に位置で仕分ける。
- 撮影・選択した写真は、長辺 2000px・JPEG品質90 に制限してから Edge Function に送る
  （`camera_hand_read_page.dart` の `_pick`）。標準カメラの写真は機種によっては数千万画素の
  ままになり得るため、無制限に送ると Claude Vision 側の処理やペイロードサイズが不安定になる。

## 2. 自動仕分け（位置ベース）

撮った1枚から、Claude Vision がカードを読み、**位置で役割を推定**する:

- **下ゾーン（区切り線の下）＝ 自分のハンド**（2枚）
- **中央（ディーラー側の並び）＝ 場**。並び順で **右から フロップ(3)→ターン(1)→リバー(1)** に割り当てる。
- **その他のかたまり＝ 相手のハンド**。**かたまり（人）ごとに分けて**認識する（相手①・相手②…）。

### 2-1. 途中で降りた/リバーまで行かない場合（重要）

- 場は可変長: **フロップのみ=3枚 / ターンまで=4枚 / リバーまで=5枚**。
  リバーはターンがある時のみ、ターンはフロップがある時のみ。5枚未満でも正常とする。
- 相手は**見えた人だけ**対象（降りて伏せたままのカードは写らないので認識しない）。
  相手の人数は写っていたかたまりの数だけ可変。**各相手はちょうど2枚**。

## 3. 確認・修正（登録画面）

- レイアウトは**縦1カラム、スマホ幅に収まる**（横スクロールさせない）。役割ごとに**1行**で並べる:
  - 自分のハンド（1行）
  - 場（フロップ→リバー）（1行）
  - 相手①（1行）／相手②（1行）… 相手ごとに1行
- 各カードに**役割プルダウン**（自分／フロップ／ターン／リバー／相手①／相手②…／除外）を付け、
  自動仕分けが違うカードだけ選び直せる。行内のカードは幅に合わせて縮め、**横スクロールは出さない**。
- **枚数チェック**: 自分=2、フロップ=3、ターン≤1、リバー≤1（かつターンがある時のみ）、各相手=2。
  外れている行に注意アイコンを出す。
- **ランク・スートの手直し（保険）**: 基本はランク・スートは正確に読めている前提だが、実卓1枚撮りは
  誤読も起きうる。**カード面をタップ→カードピッカー**（既存 `card_picker_sheet.dart`）で
  ランク・スート自体も直せるようにする。
- カメラで埋まらない項目（ポジション・有効スタック・アクション・相手傾向・ゲーム種別）は
  従来どおりユーザーが入力する。
- **自動でレビューを実行しない。** ユーザーがフォーム全体を確認して初めて `/review` に送る。

## 4. 読み取りパイプライン

```
テーブル全体の写真1枚
  → POST /read-hand   （Edge Function。Claude Vision をサーバー側で呼ぶ）
  → { cards:[{code,confidence,suggested,board_order?,cluster?}], warnings:[] }
  → 位置ヒントで自分/場/相手に自動仕分け → 確認画面にプリフィル
  → ユーザー確認・修正 → 既存 POST /review へ
```

### 4-1. `/read-hand` 出力（Structured Output で固定）

```json
{
  "cards": [
    { "code": "Ah", "confidence": 0.97, "suggested": "me" },
    { "code": "Js", "confidence": 0.96, "suggested": "me" },
    { "code": "Qs", "confidence": 0.98, "suggested": "board", "board_order": 1 },
    { "code": "7d", "confidence": 0.97, "suggested": "board", "board_order": 2 },
    { "code": "2c", "confidence": 0.95, "suggested": "board", "board_order": 3 },
    { "code": "9h", "confidence": 0.94, "suggested": "board", "board_order": 4 },
    { "code": "Ts", "confidence": 0.90, "suggested": "board", "board_order": 5 },
    { "code": "Kd", "confidence": 0.92, "suggested": "villain", "cluster": 1 },
    { "code": "Ks", "confidence": 0.93, "suggested": "villain", "cluster": 1 },
    { "code": "8c", "confidence": 0.91, "suggested": "villain", "cluster": 2 },
    { "code": "8d", "confidence": 0.90, "suggested": "villain", "cluster": 2 }
  ],
  "warnings": []
}
```

- `code` は `PlayingCard.parse`（`lib/shared/models/playing_card.dart`）準拠
  （ランク `A K Q J T 9..2` + スート `s h d c`。`10` は `T` に正規化）。
- `suggested` は `me` / `board` / `villain`。`board_order` は場の並び順（1 が右端＝フロップ1枚目）。
  `cluster` は相手の人ごとのまとまり。
- `confidence` はカードごと（0.0〜1.0）。**自信が無い時は捏造せず低信頼度で返し**、読めない位置は
  返さず `warnings` に理由（日本語）を入れる。

### 4-2. Vision プロンプト（要点／キーはサーバー側で付与）

```
あなたはポーカーのテーブル写真からカードを読み取る認識器です。
- 見えているプレイングカードのランクとスートを読み取る（A,K,Q,J,T,9..2 と s,h,d,c）。
- 各カードの画面上の位置から役割を推定する:
  画面下部の区切りゾーン=自分(me)、中央の並び=場(board、右から順に board_order を振る)、
  その他のかたまり=相手(villain、人ごとに cluster を振る)。
- 読めないカードは推測で埋めない。自信が低い場合は confidence を下げる。
- 出力は指定 JSON スキーマのみ。チップ額・人物などカード以外は読み取らない。
```

## 5. バリデーション

- 全体で**カード重複を禁止**（既存 `HandReviewInput.usedCards` を利用）。重複は未確定扱いにして確認を促す。
- 不正コード（存在しないランク/スート）は破棄して `warnings` 化。
- 枚数: 自分=2 / フロップ=3 / ターン≤1 / リバー≤1（ターンがある時のみ）/ 各相手=2。外れは注意表示。

## 6. 権限・プライバシー

- カメラ権限（iOS: `NSCameraUsageDescription` / Android: `CAMERA`）を追加。
- 画像は Edge Function 経由で Claude に送る。**原則として画像は保存しない**（読み取り後に破棄）。
- 送るのはカード読み取りに必要な画像のみ。背景の個人情報は枠外にするよう撮影ガイドで促す。

## 7. Edge Function エンドポイント追加

`docs/ai-prompts.md` の表に `POST /read-hand`（Claude Vision）を追加済み。

## 8. スコープ / 段階

- **MVP**: 1枚撮影 → `/read-hand`（Claude Vision）→ 位置で自動仕分け → 確認画面（役割プルダウン＋
  ランク/スート手直し）→ 既存 `/review`。
- **次段階**: 相手人数の可変UI、読み取り精度に応じた再撮影導線、（将来）オンラインのスクリーンショット対応。

## 9. 未決事項

- 使用する Claude モデル ID とコスト見積もりは実装フェーズで確定。
- 相手のかたまり自動分割の精度が不足する場合、確認画面で「相手を分ける/まとめる」操作を補助として検討。
